## 주요 단계 및 이벤트 흐름

### UC-01  일정 생성/수정

1. **\[사용자]** 캘린더에서 날짜·시간 슬롯 선택
2. **\[사용자]** 이벤트 제목·설명 입력 후 **저장** 클릭
3. **\[시스템]** 입력값 검증 후 `events` 테이블에 INSERT/UPDATE
4. **\[시스템]** Supabase Realtime 채널을 통해 모든 클라이언트에 브로드캐스트 (목표 ≤1 s)
5. **\[사용자]** 화면에 새 이벤트가 즉시 표시됨
   **Verification:** 이벤트 레코드가 DB에 존재하고 다른 사용자의 뷰에도 동기화되었는지 확인

### UC-02  공휴일 자동 수집 (야간 배치)

1. **\[시스템]** 매일 02:00 KST 크론 트리거 실행
2. **\[시스템]** Naver Calendar API 호출 → KR 공휴일 JSON 수신
3. **\[시스템]** 신규·변경 공휴일만 `holidays` 테이블 UPSERT
4. **\[시스템]** “holiday-update” 이벤트를 Realtime으로 송신
   **Verification:** 당해 연도의 공휴일 개수가 참조 API와 일치

### UC-03  평일 on-call 자동 배정

1. **\[시스템]** 매일 00:05 KST 크론 실행
2. **\[시스템]** 오늘이 **월–금** && 공휴일 아님인지 확인
3. **\[시스템]** `roster` 테이블에서 최신 순번 조회 → 다음 담당자 계산
4. **\[시스템]** 당일 on-call 이벤트 자동 생성 후 캘린더에 반영
   **Verification:** 오늘 날짜에 정확히 1개의 on-call 이벤트가 존재

### UC-04  PDF 다운로드

1. **\[사용자]** 캘린더 우측 상단 **PDF 내보내기** 클릭
2. **\[사용자]** 범위(월/주) 선택 → **미리보기** 확인
3. **\[시스템]** 클라이언트에서 `pdf-lib`로 레이아웃 렌더링
4. **\[시스템]** Blob 스트림을 사용자 브라우저에 반환 → 저장 다이얼로그 표시
   **Verification:** 파일 크기·페이지 수가 미리보기와 일치, 열어 보면 일정이 정확

## 대안 흐름 및 엣지 케이스

| 조건                   | 분기 흐름                                        | 처리 후 상태              |
| -------------------- | -------------------------------------------- | -------------------- |
| 동일 슬롯 중복 이벤트         | **\[시스템]** “병합 vs 덮어쓰기” 모달 표시 → 선택값 적용       | 최종 1개 레코드만 유지        |
| 저장 중 네트워크 오프라인       | **\[시스템]** 로컬 IndexedDB 대기열 저장 → 연결 복구 시 동기화 | 사용자에게 “오프라인 저장됨” 토스트 |
| 공휴일 API 3회 연속 실패     | “import-error” 플래그 기록, 관리자에게 Slack 알림        | 다음 날 재시도             |
| PDF 렌더링 오류(폰트 불일치 등) | **\[시스템]** 토스트 “내보내기 실패” + 오류 로그             | 재시도 가능 상태            |

## 비즈니스 규칙 & 제약

1. on-call 배정은 **Mon-Fri** & **공휴일 제외**.
2. *@company.com* 이메일만 접근(RLS).
3. 과거 **30일**이 지난 달은 관리자만 수정 가능.
4. 실시간 지연 목표 ≤ 1 초.
5. Supabase·Vercel Free Tier 한도 내 운영 (DB ≤ 500 MB, 대역폭 ≤ 100 GB/월).

## UI 고려 사항

* **모바일 우선**: 하단 탭 내비게이션·풀스크린 모달
* **데스크탑**: 사이드바 고정, drag-and-drop 지원
* **알림**: ARIA `live` 적용, 색상 대비 4.5:1 이상
* **오프라인 표시**: 상단 배너 “오프라인 모드” (회색)
* **검증 입력**: 잘못된 날짜 형식 즉시 빨간 outline & 설명 텍스트

## 데이터 요구사항 & 데이터 흐름

### 테이블 요약

| 테이블             | 주요 필드                                    | 관계        |
| --------------- | ---------------------------------------- | --------- |
| `events`        | id, title, start, end, owner\_email, tag | 1\:N(사용자) |
| `holidays`      | date, name                               | (캘린더 참고)  |
| `roster`        | date, assignee\_email                    | N:1(사용자)  |
| `user_settings` | email(PK), notify\_email, notify\_slack  | 1:1       |

### 데이터 플로우(텍스트 다이어그램)

```
[Browser] ⇄ (JWT) ⇄ [Supabase Realtime]
       ⇅                         ⇡
 PDF/lib  → Blob → Download   Cron Jobs
       ↘︎                          ↗︎
    [Naver API]--------(공휴일)-------
```

## 보안 및 개인정보 보호

* **인증**: Supabase Magic-Link(JWT, HS256)·Token 만료 1 h
* **전송**: HTTPS-only, HSTS, WebSocket WSS
* **저장**: PII 최소화 – 이메일 외 정보 미저장
* **권한**: Row-Level Security → `owner_email = auth.email()`
* **감사**: Supabase Audit 로그 + Vercel Access Log 30 일 보관
* **백업**: 매일 DB dump → Supabase Storage(암호화)
